# peer-discovery

Приложение обнаруживает другие запущенные копии самого себя в локальной сети через периодические multicast UDP heartbeat-сообщения и печатает список IP-адресов «живых» копий при каждом изменении их состава.

Поддерживает IPv4 и IPv6 — протокол выбирается автоматически по типу переданного multicast-адреса.

## Запуск

```
./peer-discovery <multicast-адрес> [порт=4446]
```

| Аргумент | Обязательный | Описание |
|---|---|---|
| `<multicast-адрес>` | да | Адрес multicast-группы (IPv4 / IPv6) |
| `[порт]` | нет | UDP-порт, по умолчанию `4446` |

Примеры:

```
./peer-discovery 239.0.0.1 5000     # IPv4
./peer-discovery ff05::1 5000       # IPv6
```

Запустим несколько экземпляров (в разных терминалах или на разных машинах в одной сети) с одинаковым адресом и портом — каждый начнёт печатать список IP остальных живых копий.

## Docker

В проекте есть готовые конфиги для запуска нескольких копий в изолированной сети Docker с поддержкой multicast.

Файлы:

- `docker.yml` — создаёт сеть `lab_1_lan` с IPv4 (`172.20.0.0/24`) и IPv6 (`fd00:20::/64`);
- `docker4.yml` — два контейнера для IPv4-режима (`peer-a4`, `peer-b4`);
- `docker6.yml` — два контейнера для IPv6-режима (`peer-a6`, `peer-b6`);
- `Dockerfile` — образ для сборки приложения.

### IPv4

```
docker compose -f docker.yml -f docker4.yml up --build
```

### IPv6

```
docker compose -f docker.yml -f docker6.yml up --build
```

### Остановка

```
docker compose -f docker.yml -f docker4.yml down
docker compose -f docker.yml -f docker6.yml down
```

## Как это работает

При старте каждая копия создаёт два UDP-сокета: `recv_sock` для приёма (bind на порт и подписка на multicast-группу) и `send_sock` для отправки. Включены `SO_REUSEADDR` и `SO_REUSEPORT`, чтобы несколько копий могли работать на одной машине.

Каждые 2 секунды копия рассылает в multicast-группу сообщение `PEER`. Протокол IPv4/IPv6 определяется автоматически по типу переданного адреса через `inet_pton`: для IPv4 используется `IP_ADD_MEMBERSHIP`, для IPv6 — `IPV6_JOIN_GROUP`.

Отдельный поток принимает датаграммы через `select()` с таймаутом 100 мс, проверяет сигнатуру и запоминает узел по ключу `IP:PORT` вместе со временем последнего пакета.

Фоновый поток каждые 100 мс проверяет, не "умер" ли какой-то узел (нет heartbeat дольше 6 секунд) — если да, узел считается умершим и удаляется.

Список печатается заново при любом изменении набора живых IP-адресов (появление нового узла, исчезновение старого).

Корректное завершение: по `SIGINT`/`SIGTERM` флаг `run` сбрасывается, оба потока завершаются, сокеты закрываются в деструкторе.

## Пример работы

```
$ ./peer-discovery 239.0.0.1             
[+] 127.0.0.1:56072  
Alive peers (1):  
  127.0.0.1:56072  
[+] 127.0.0.1:61729  
Alive peers (2):  
  127.0.0.1:56072  
  127.0.0.1:61729
```

После `Ctrl+C` на одной из копий, через ~6 секунд у оставшейся:

```
[-] 127.0.0.1:56072  
Alive peers (1):  
  127.0.0.1:61729
```

- `[+]` — обнаружен новый узел;
- `[-]` — узел пропал (таймаут);
- `Alive peers` — актуальный список «живых» копий.

## Константы (`include/common.h`)

| Константа | Значение | Назначение |
|---|---|---|
| `DEFAULT_PORT` | 4446 | Порт multicast-группы по умолчанию |
| `SEND_INTERVAL_MS` | 2000 | Интервал рассылки heartbeat-сообщений, мс |
| `SLEEP_STEP_MS` | 100 | Шаг сна в цикле отправки, мс |
| `TIMEOUT_MS` | 6000 | Таймаут узла, мс |
| `BUF_SIZE` | 64 | Размер буфера приёма |
| `PEER_MSG` | `"PEER"` | Сигнатура сообщения |
| `PEER_MSG_LEN` | 4 | Длина сигнатуры, байт |
| `SELECT_TIMEOUT_US` | 100000 | Таймаут `select()`, мкс |

---

## Особенности

- Работает в пределах одного multicast-домена (TTL = 1).
- Ключ узла — пара `IP:PORT`; несколько копий на одной машине различаются портом.
